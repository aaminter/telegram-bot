# Telegram Bot

![Java CI](https://github.com/aaminter/telegram-bot/actions/workflows/ci.yml/badge.svg)

Учебный backend-проект на Java и Spring Boot. Репозиторий демонстрирует работу с Telegram Bot API, PostgreSQL, Liquibase и планированием фоновых задач.

> Статус: учебный проект в развитии. Описание фиксирует назначение и техническую основу репозитория; функциональность следует считать реализованной только в той мере, в какой она подтверждена исходным кодом и тестами.

## Цель проекта

Создать Telegram-бота с серверной бизнес-логикой и устойчивым хранением данных. Проект используется для практики разработки backend-сервисов, интеграции внешнего API и организации фоновых операций.

## Технологии

- Java 11
- Spring Boot 2.6.5
- Spring Web
- PostgreSQL
- Spring Data JPA
- Liquibase
- Telegram Bot API (pengrad)
- Maven
- JUnit / Spring Boot Test

## Архитектурные границы

Ожидаемое разделение ответственности:

- **Telegram integration**: получение обновлений и отправка ответов через Telegram API.
- **Application/service layer**: сценарии и бизнес-правила.
- **Persistence layer**: хранение данных через JPA и PostgreSQL.
- **Database migrations**: версионирование схемы через Liquibase.
- **Scheduling**: выполнение отложенных и периодических задач.

Фактическую структуру и реализованные сценарии см. в `src/main/java` и Liquibase changelog.

## Конфигурация

Секреты и параметры окружения не хранятся в репозитории.

Необходимые переменные:

| Переменная | Назначение |
|---|---|
| `DB_URL` | JDBC URL PostgreSQL |
| `DB_USERNAME` | Пользователь БД |
| `DB_PASSWORD` | Пароль БД |
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота |

Перед запуском создай локальные переменные окружения. Не добавляй реальные токены, пароли и дампы БД в Git.

## Запуск

1. Установи JDK 11 и Maven.
2. Подними PostgreSQL и создай отдельную базу данных.
3. Задай перечисленные выше переменные окружения.
4. Запусти приложение:

```bash
mvn spring-boot:run
```

Сборка:

```bash
mvn clean verify
```

Команды требуют настроенного окружения и доступной БД.
